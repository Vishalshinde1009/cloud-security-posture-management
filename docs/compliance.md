# Compliance Framework Engine

## Overview

The Cloud Security Posture Management (CSPM) platform incorporates an automated compliance framework engine that maps discovered security findings against standard industry security controls.

> **CRITICAL DISCLAIMER**:
> Compliance evaluations generated by this platform are for **academic and internal posture assessment only**. This platform **does NOT grant official regulatory or statutory certification** for CIS, NIST, ISO, or PCI DSS standards. Statements within this system refer exclusively to **"Security Control Status"**, **"Control Coverage"**, **"Mapped Findings"**, and **"Potential Gaps"**.

## Evaluation Logic & Formulas

### Control Status Determination

For each control mapped to one or more security detection rules:
- **`NON_COMPLIANT`**: At least one active (status `OPEN` or `IN_PROGRESS`) finding is linked to an underlying rule associated with this control.
- **`COMPLIANT`**: All security rules associated with the control have been evaluated and have **zero** active non-compliant findings (e.g. findings are either resolved, accepted, or no violations detected).

### Control Coverage Percentage

Compliance coverage measures the ratio of passing controls to total evaluated controls for a given framework:

$$\text{Coverage Rate (\%)} = \left( \frac{\text{Number of COMPLIANT Controls}}{\text{Total Controls in Framework}} \right) \times 100$$

Where:
- $\text{Total Controls} = \text{Passed Controls} + \text{Failed Controls}$
- Rates are strictly bounded between $0\%$ and $100\%$.

## Control Catalog Sample Mappings

### CIS AWS Benchmark
- **CIS-1.4**: Ensure multi-factor authentication (MFA) is enabled for all IAM users with console access (`IAM-001`)
- **CIS-1.16**: Ensure IAM policies are attached only to groups or roles (`IAM-002`)
- **CIS-2.1.1**: Ensure all S3 buckets employ encryption at rest (`S3-002`)
- **CIS-2.1.2**: Ensure S3 Bucket Policy denies insecure HTTP requests (`S3-005`)
- **CIS-2.1.5**: Ensure S3 bucket public access block is enabled (`S3-001`)
- **CIS-3.1**: Ensure CloudTrail is enabled in all regions (`CT-003`)
- **CIS-3.4**: Ensure CloudTrail log file validation is enabled (`CT-002`)
- **CIS-4.1**: Ensure no Security Groups allow ingress from 0.0.0.0/0 to port 22 (`EC2-002`, `NET-001`)
- **CIS-4.2**: Ensure no Security Groups allow ingress from 0.0.0.0/0 to port 3389 (`EC2-003`, `NET-002`)
- **CIS-4.3**: Ensure the default security group restricts all traffic (`NET-004`)
- **CIS-2.3.1**: Ensure RDS instances have encryption at rest enabled (`RDS-002`)
- **CIS-2.3.2**: Ensure RDS database instances are not publicly accessible (`RDS-001`, `RDS-003`)

## API Endpoints

- `GET /api/compliance/frameworks`: Lists all 4 frameworks with high-level coverage stats.
- `GET /api/compliance/{framework}/summary`: Comprehensive summary with coverage percentage, passing vs failing count, and breakdown by service.
- `GET /api/compliance/{framework}/controls`: Complete list of controls with mapped active findings, severity, and remediation instructions. Supports filtering by `status_filter` and `service_filter`.
